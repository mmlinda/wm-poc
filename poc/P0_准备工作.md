# P0 准备工作

## 最快路径：只做一件事

```bash
python poc/setup_and_run.py --sync      # 第一次建议带 --sync：顺手把工作流推到仓库
python poc/setup_and_run.py            # 之后重跑不用带
```

> **为什么要 --sync**：dispatch 用的是**仓库里那份**工作流。本地改好但没 push，一样 422，
> 而 GitHub 的报错（"does not have workflow_dispatch trigger"）根本看不出是这个原因。
> `--sync` 会用 Contents API 把 `watermark_poc.yml` / `poc/*.py` 推上去，并在推之前先做 YAML 体检。
> 需要 PAT 勾上 **Contents: Read and write**（只有 Actions 权限会 403）。

它会**逐项问你要凭据 → 当场校验 → 通过后写 `.env.poc` → 自动部署 Worker（如果给了 CF Token）→ 直接跑 P1~P5**。
凭据你只需要去三个网站点几下拿到（下面第二节写了从哪复制），**不用手动改任何文件**。

- 想先只配不跑：`python poc/setup_and_run.py --skip-run`
- 工作流改过、想把本地版本推到仓库：`python poc/setup_and_run.py --reuse --sync`
- YAML 体检单独跑：`python -c "import sys;sys.path.insert(0,'poc');from setup_and_run import lint_workflow;print(lint_workflow('poc/watermark_poc.yml'))"`
- 已经配过一次，想重跑：`python poc/setup_and_run.py --reuse`
- 想顺手压一下并发：`python poc/setup_and_run.py --reuse --p6 3`

**没有任何第三方依赖**（纯标准库），不需要 pip install。

## 二、你要拿的 5 个东西（按顺序，20 分钟）

### ① Turso（5 分钟）
1. https://turso.tech → Sign up（GitHub 或邮箱登录，免费）
2. `Create Database` → 名字 `wm-poc` → Region 选离你近的（`aws-ap-northeast-1` 东京 / `aws-ap-southeast-1` 新加坡）
3. 建好后点进去，复制两样：
   - **Database URL**：`libsql://wm-poc-xxxx.turso.io`
   - **Token**：`Create Token` → 复制（长期有效，形如 `eyJhbGciOi...`）
4. 顺手把 `poc/schema.sql` 贴进它自带的 SQL Console 跑一遍（**这一步能立刻暴露 SQL 不兼容**）

**交给我**：`TURSO_URL=...` 和 `TURSO_TOKEN=...`

### ② Cloudflare 账号 + R2（8 分钟）
1. https://dash.cloudflare.com → Sign up（免费，**不需要绑卡也能用 Workers**）
2. 左侧 `R2 Object Storage` → 首次会让你建 bucket：名字 `wm-poc`（**建 R2 可能要绑卡做验证**；
   如果卡在这一步，先跳过 R2，我用 Worker 内存 + base64 兜一天，验证完再补）
3. R2 → `Manage R2 API Tokens` → `Create API token` → 权限选 **Object Read & Write**，范围只选 `wm-poc` 这个桶
   → 记下 **Access Key ID / Secret Access Key / Endpoint**（`https://<accountid>.r2.cloudflarestorage.com`）
4. 记下你的 **Account ID**（右侧栏）

**交给我**：`R2_ENDPOINT` / `R2_AK` / `R2_SK` / `R2_BUCKET=wm-poc`

### ③ GitHub public 仓库 + PAT（7 分钟）
1. 新建**公开**仓库（名字随意，如 `wm-poc`），**不要**放任何真实数据/密钥
2. 把 `poc/watermark_poc.yml` 放到 `.github/workflows/`；把 `wm-portal/` 整个目录（已脱敏）传上去
3. Settings → Developer settings → **Fine-grained token**：
   - 只授权这一个仓库
   - 权限勾 **Actions: Read and write**（`Contents: Read` 会自动带上）
   - 有效期设 7 天（PoC 用完就删）
4. 记下仓库全名：`你的用户名/wm-poc`

**交给我**：`GH_REPO=用户名/wm-poc` 和 `GH_PAT=github_pat_...`

### ④ Worker（我拿到 token 后 5 分钟部署，你也可以自己来）
需要 `wrangler` 或 Dashboard 粘贴。**最省事：你只给我 ③ 的 PAT 和 ② 的 CF API Token**
（权限：`Workers Scripts:Edit` + `Workers KV:Edit` + `R2:Edit`），我用 API 直接部署。

### ⑤ 一个短字符串当 `CB_SECRET`
随便 32 位，比如 `openssl rand -hex 16` 的结果。**别用生产密钥**。

## 三、交给我之后，我按这个顺序跑（预计 40 分钟出全部数字）

| 步 | 动作 | 产出数字 |
|---|---|---|
| P1 | `poc_check.py turso`（建表 + 写读 + 延迟） | Turso 写/读 p50 |
| P2 | 用 PAT 触发 `watermark-poc.yml`（空跑 + 真打 1 本） | **t_queue / t_install / t_ready / t_book** |
| P3 | 母本 → R2 → 打标 → 成品 → R2 → 下载校验 | 单本耗时、上传耗时、文件大小 |
| P4 | Worker dispatch → runner 领任务 → 回调 → 前端轮询 | t_dispatch、端到端 |
| P5 | 2 本写 `wm_mapping`，Worker 按 watermark_id 反查 | 一致率 |
| P6 | batch=1 连发 5 个 / batch=10 发 2 个 | 并发吞吐、排队曲线 |

## 四、已经可以给你看的三个数（本地，不代表云）

| 指标 | 实测 | 说明 |
|---|---|---|
| 建批次 + dispatch | **27 ms** | 含 1 次 DB 写 + 1 次 GH API（本地拦截） |
| 轮询查状态 p50 | **7 ms** | 主键查 1 行，`no-store` |
| **领取"秒下"** | **8 ms** | 命中成品 → 直接签 URL，**完全不触发 Actions** |

> 这三个数证明"预生成为主"这条路是对的：领取端 8ms 就能给链接，跟 Actions 的快慢**彻底解耦**。
> 唯一还缺的是"没命中时"那条路要多久 —— 那就是 P2 的 `t_ready`，必须真跑 Actions。
